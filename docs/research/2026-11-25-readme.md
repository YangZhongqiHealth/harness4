# README presentation research

Reviewed 2026-11-25. This is an editorial review of official project READMEs, not a
ranking of their software or evidence that a particular layout causes adoption.

| Reference | Presentation pattern observed | Applied to Harness4 |
|---|---|---|
| [Hermes Agent](https://github.com/NousResearch/hermes-agent/blob/main/README.md) | Leads with a distinct identity, learning-oriented promise, benefit table and direct installation path. | Give the learning loop a prominent position and describe concrete user outcomes before implementation details. |
| [OpenHands](https://github.com/OpenHands/OpenHands/blob/main/README.md) | Uses a clear product category, navigation links, visual preview and feature-to-documentation links. | Add a compact header, navigation, two workflow diagrams and clear routes into operational docs. |
| [Aider](https://github.com/Aider-AI/aider/blob/main/README.md) | Makes its terminal use case immediately recognizable, shows the experience early and organizes features around user tasks. | Put a runnable, credential-free demonstration near the top, with a small excerpt of actual output. |
| [GEPA](https://github.com/gepa-ai/gepa/blob/main/README.md) | Explains the optimization mechanism, links evidence, and connects the value proposition to executable examples. | Explain the learning mechanism and link our own validation and research. Keep synthetic lifecycle evidence distinct from model-quality measurements. |

## Editorial choices

The README is the front door: identity → benefits → first successful run → execution
and learning diagrams → maturity/evidence → docs → contribution. Detailed local CLI
semantics move into docs/LOCAL_REVIEW.md; GitHub, provider and learning guides remain
the authoritative operational references.

Use native Mermaid diagrams so the flow stays editable, searchable and reviewable in
Git. Label model actions separately from CI, policy and operator decisions. Show the
failure/abstention path and rollback, not just a happy-path arrow. Keep all text in
the surrounding prose too, so the explanation works without diagram rendering.

Use real CI/license/runtime badges, an actual demo excerpt and current validation
counts. Do not borrow another project's branding, metrics, endorsements or superlative
claims. Do not imply universal model compatibility, autonomous background learning,
production qualification or a measured lead over Claude Ship. The project's Harness
4.0 direction and its current alpha package version are stated separately.

## Editorial review and revision — 2026-11-26

The first implementation accumulated repeated benefits, three competing diagrams,
a lengthy comparison and multiple entry-point tables. In the actual narrow GitHub
view, Mermaid labels became small and navigation controls obscured end nodes. The
JSON demo needed a clearer explanation of what had changed and what it proved.

The revision reduces the README from 2,042 to 1,160 whitespace-delimited words.
One repository-owned SVG introduces the two connected loops with deliberate spacing,
large labels, a fixed contrast palette, accessible title/description and Markdown
alternative text. It contains no scripts, external fonts or fetched assets. Detailed
Mermaid workflows remain in docs/WORKFLOWS.md for technical readers.

The information order is now positioning → visual mechanism → runnable demo → three
adoption steps → concrete learning example → concise comparison → maturity and docs.
The comparison's detail moves to docs/COMPARISON.md. Official Claude Ship product and
overview pages were checked again on 2026-11-26. Unknown competitor capabilities stay
unknown; live Harness4 quality/cost superiority is not implied.

## Positioning refinement — 2026-11-26

Lead with “An open-source alternative to Claude Ship—with a verifiable
self-improvement loop.” Follow immediately with the PR workflow and the actual
learnable surface (review checklists), then distinguish tested lifecycle mechanics
from unmeasured live gains. Keep Harness4 until a separate naming decision.

Editorial changes: benefits tied to controls; one existing overview illustration;
a credential-free runnable demo; a missing-measurement example with evaluation and
release gates; explicit observe/repair/approval/learning modes; balanced comparison;
current capabilities beside concrete next milestones. Preserve established anchors.

Rechecked primary comparison sources:
- https://code.claude.com/docs/en/claude-ship
- https://claude.com/product/claude-ship

Use “alternative,” not an official open-source edition or a demonstrated superior
replacement. Public docs describe broader Claude Ship stewardship; absence of an
explicit learning-release mechanism in these pages is not proof of internal absence.
