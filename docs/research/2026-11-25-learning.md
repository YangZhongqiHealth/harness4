# Evidence-gated harness learning: research and implementation decisions

Research date: 2026-11-25. This is a targeted primary-source review, not an exhaustive
systematic review or a claim that one algorithm is universally SOTA. Papers use
different models, environments, budgets and feedback. Their reported improvements
cannot be transferred to Harness4 or compared directly with Claude Ship.

## What the evidence supports

| Work / primary source | Useful mechanism | Limitation / decision for Harness4 |
|---|---|---|
| [Reflexion, 2023](https://arxiv.org/abs/2303.11366) | Converts task feedback into reusable verbal lessons without weight updates | Reflection is a proposal, not independent evidence of correctness. Keep feedback provenance and counterexamples. |
| [GEPA, 2025; revised 2026](https://arxiv.org/html/2507.19457v2) | Trace-conditioned prompt edits, per-example evaluation, diverse candidate archive and Pareto selection | Adopt bounded reflective proposals and archive all attempts. Use dev-only selection and a separate release cohort. This implementation is not a reproduction of GEPA's genetic/Pareto search. |
| [ACE, 2025](https://arxiv.org/html/2510.04618v1) | Structured, incremental playbook changes reduce loss of useful detail during repeated rewriting | Keep a small named review-checklist section; preserve the fixed review contract. Cap its size. The paper itself notes dependence on reflection quality and that richer context is not always useful. |
| [Meta-Harness, 2026](https://arxiv.org/abs/2603.28052), [official code](https://github.com/stanford-iris-lab/meta-harness) | Search the harness around a fixed model; retain experiment history and domain-specific evaluation | Learn only a bounded text surface initially. Generated executable harness changes need a separate sandbox and reviewed software release. |
| [AutoSaddler, 2026](https://github.com/microsoft/AutoSaddler) | Trace diagnosis, typed interventions, development validation, durable provenance and candidate lineage | Adopt immutable episodes, candidate ancestry, durable cycle state and auditable decisions. Its current development-selection mechanism does not by itself constitute our independent production release gate. |
| [Hermit, 2026](https://infini-ai-lab.github.io/hermit/) | A trainable external adapter can leave the underlying agent and model fixed | Keep the learner outside GitHub write authority; the adapter supplies review guidance, never capabilities or release decisions. |

| [Darwin Gödel Machine, 2025/2026](https://arxiv.org/abs/2505.22954) | Archive-based exploration can preserve useful branches rather than keeping only the latest attempt | Preserve rejected candidates and lineage. Open-ended self-modifying code is outside this release's threat model. |
| [Meta RAM self-improving memory, 2026](https://facebookresearch.github.io/RAM/blogs/self_improving_memory/) | Evaluating and selecting generated memory-harness revisions is essential | This is an author research report, not independent validation of our system. We do not implement the paper's differentially private reusable-holdout algorithm. |

A recent [November 2026 framework paper](https://arxiv.org/abs/2611.22299) also
organizes harness adaptation across context, control, actions and verification.
We use it as a taxonomy, not as evidence that a new name establishes a generation
of capability. Sources above were opened directly; implementation decisions below
are our engineering synthesis, not claims made by the cited authors.

## Our synthesis

Two loops share provenance but not authority. The execution loop reviews and repairs
PRs under an operator-owned GitHub policy. The learning loop proposes a replacement
for `review_checklist` from consented, revision-bound development feedback. It cannot
edit the fixed review prompt, tools, credentials, required checks, write grants,
evaluator, model identity or budgets.

1. Capture immutable review inputs, outputs, model profile and policy version.
2. Let the local operator attach verified, revision-bound finding labels and an
   independent source-group identifier. A model's self-assessment is not a label.
3. Freeze development, held-out target and retention-anchor cohorts before search.
   Detect overlapping source groups and duplicate inputs, not just duplicate IDs.
4. Evaluate the incumbent on development cases. Generate a bounded number of
   reflective candidates using development inputs, labels and error traces only.
   Archive invalid/rejected attempts; select at most one winner on dev performance.
5. Before any held-out call, durably consume the release cohort. Run both policies
   afresh with the same model profile and identical no-tool review pipeline.
   Expected findings, split names and group identifiers never enter rollout prompts.
6. The trusted evaluator compares the union of the two review passes with curated
   expected finding locations/severities. Exact matching is deliberately narrow:
   it detects omitted and extra findings but does not resolve semantic ambiguity.
7. Require adequate independent groups, target improvement with a conservative
   confidence bound, no observed anchor regressions and an upper bound on anchor
   regression risk. Incomplete runs, model drift or exhausted budgets abstain.
8. A separate explicit operator action approves the exact persisted report. Atomic
   compare-and-swap checks the active generation, parent, scope, profile, evidence,
   expiry and one-use approval. A successful release affects future runs only.
9. Rollback switches to a previously active, compatible, non-revoked policy with an
   audit event. It does not reverse GitHub commits or reviews. Retracting evidence
   revokes dependent candidates and returns an affected active policy to baseline.

## Statistical contract and its limits

The live gate averages paired binary exact-match differences within each source
group, then treats groups as independent sampling units. Differences lie in [-1,1].
For n target groups, a one-sided Hoeffding lower bound is
`mean_gain - sqrt(2 * log(1/alpha_target) / n)`. For anchors, any observed regression
rejects; with zero regressing groups the exact one-sided binomial upper bound is
`1 - alpha_anchor ** (1/n)`. Split the total alpha equally between the two bounds
(union bound). The defaults require at least 100 target and 100 anchor groups,
a positive practically meaningful lower-bound gain and at most 5% anchor-regression
risk. These bounds are conservative and often abstain; they are not a power analysis.

Validity assumes independently sampled groups, correct labels, a representative
cohort, stable model behavior and a protocol chosen before optimization. Group IDs
are operator attestations; software cannot prove independence. Future repeated cycles
need fresh cohorts, and each report is a per-cycle statement, not a lifetime error
budget. A benchmark already public or known to the model may be contaminated even
when our local split checks pass. Missing outcomes are never silently discarded.

## What we deliberately do not adopt

- Unrestricted self-editing of the runtime, permissions or evaluator.
- Treating confidence, a thumbs-up, or the learner's own judgment as ground truth.
- Promoting after one successful PR or repeatedly querying the same release set.
- Optimizing only recall while hiding false positives or regressions.
- Claiming performance gains from a scripted fixture. Demo and production scopes
  are distinct and scripted evidence cannot activate production behavior.
- Claiming SOTA, superiority over Claude Ship, or general intelligence from test
  counts. Such claims require a public, cost-matched, independently labeled benchmark.
